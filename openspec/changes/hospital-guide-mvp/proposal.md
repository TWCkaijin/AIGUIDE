# Proposal

> 來源：第五組 SDD 訪談(見專案根目錄 `AI-specification.md`)。本文件只轉寫小組回答，標示「待確認 #n」者對應 `AI-specification.md` 文末清單。

## Why

一般病患或家屬不熟悉醫院環境，在就醫過程「站點與站點之間」容易走錯樓層、在原地問人、拿著單子不知道下一站，造成過號、檢查延誤、多走冤枉路與反覆詢問櫃台。醫院端則希望能預測抵達時間與人流、讓使用者追蹤叫號，以減少非預期等待時間。

- 證據來源：親身經驗、預期行為、實際案例(待確認 #1)
- 照護價值指標：就醫流程平均完成時間(計時起點：使用者按下開始導覽或每個 stage 開始時；終點：抵達下一個站點時)、必要步驟正確完成率(待確認 #3)；基準值與目標值(待確認 #4)

## What Changes

新建「醫院通」網頁原型，服務初診病人、行動不便者、長者、陪診家屬(無明確排除對象)：

- 病人以身分證字號/健保卡 + 手機簡訊認證登入，只看今日行程(簡訊、院內限定為 mock)
- 使用者以簡短文字描述今日到院預辦事務，由院內離線自架 LLM 判斷下一站與路線
- LLM 輸出須通過流程依賴檢查，違規重新產生，3 次失敗引導至櫃檯
- 顯示步行時間、預計等候、目前叫號、整趟預估時間(叫號與預測為 mock)
- 站點人員登錄完成與到站核查(登錄為 mock)
- 臨時變動即時通知受影響使用者
- 「我需要求助」按鈕與院內通報
- 護理行政後台：資料維護、模型設定變更需簽核並保留版本紀錄

## Capabilities

### New Capabilities

- `patient-access`：病人登入、身分驗證、資料取用範圍與無障礙需求收集
- `journey-guidance`：依今日事務由 LLM 規劃下一站與路線，並受流程依賴與檢查機制約束
- `ai-guardrails`：AI 回應範圍限制、模型部署位置與送入 LLM 的資料白名單
- `visit-time-info`：步行時間、等候時間、叫號與整趟預估時間的顯示
- `station-checkpoint`：站點人員登錄完成與到站核查
- `live-change-notice`：臨時變動的更新與受影響使用者通知
- `emergency-help`：求助按鈕與院內通報
- `admin-console`：護理行政後台的資料維護與模型設定變更管理

### Modified Capabilities

(無，專案目前沒有既有 spec)
